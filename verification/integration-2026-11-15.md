- Home 서버 목록/메뉴/정렬과 Search 실제 검색/최근 기록/대표 메뉴/전체 메뉴를 각각 유지했다.

## Home 메뉴 진입 진단
실제 화면에는 안성휴게소 메뉴와 사진·가격이 표시됐지만 UiAutomation은 이전 Home 노드를 반환했다. 검사에서 노드 캐시를 비우자 메뉴 화면을 정상 인식했다. 앱의 메뉴 진입 연결은 정상이며, 검사에 단일 태스크 실행/보이는 노드 필터/접근성 서비스 유지/화면 준비 대기를 적용했다.

## 실행 검증
최종 통과 환경: 별도 `RestStop_API34` AVD, Android 14/API 34, 1600x1000, density 160, software GPU.

- 게스트 버튼으로 Home 진입.
- `phase integration`: PASS. Home 카드→메뉴, 낮은 가격순 4,000원부터 오름차순, 뒤로가기, Home 스크롤 위치 유지.
- 같은 검사에서 한글 안성 검색→대표 안성국밥 10,000원→전체 메뉴 28개→마지막 속풀이생라면 6,000원까지 스크롤→대표 메뉴→닫기 확인.
- Search→My(8회)→Search에서 검색 필터 유지, 검색어 지우기 후 실제 최근 항목 확인, Home 복귀.
- `phase integration-restore`: PASS. 앱 강제 종료 후 게스트 Home과 최근 검색 기록 복원, 저장 항목의 대표 메뉴 열기 확인.
- 실제 터치 입력으로 Home 메뉴 진입/정렬/뒤로가기 및 가로 드래그 확인. 보이는 휴게소가 안성·망향에서 망향·천안호두·옥산으로 바뀜.

검사 과정에서 안성휴게소를 최근 기록에 추가한다. 기존 데이터를 삭제하지 않는다.

## Pleos 확인 범위와 제약
Pleos Connect v2.1.0에서는 통합 앱 실행과 Home 서버 응답/메뉴 요청 성공을 확인했으나, 검은 화면과 프로필 하드웨어·차량 제어 서비스 반복 종료가 발생했다. 최종 전체 시나리오 PASS는 위의 일반 Android 14 AVD 결과이며 Pleos 전체 시나리오 통과로 간주하지 않는다. 원래 Pleos AVD의 앱 데이터를 삭제하거나 초기화하지 않았다.

Home 위치는 PR의 고정 시연 좌표이며 실제 차량 위치 SDK 연결은 이번 작업 범위가 아니다. My 방문/식사 기록과 8회는 목데이터다.

## 재현
게스트 로그인 상태에서 README의 integration / integration-restore 명령을 실행한다. 정상 결과에는 `verification=PASS`가 표시된다. 셸 종료 코드만으로 통과 여부를 판단하지 않는다.

추가 실제 터치 확인: Search의 전체 메뉴 화면을 손가락 드래그 입력으로 아래로 이동시켜 다른 메뉴 행이 표시되는 것을 확인했고, 대표 메뉴로 복귀→닫기→My의 8회 표시→Home 복귀까지 확인했다.
